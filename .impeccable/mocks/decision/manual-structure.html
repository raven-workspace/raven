They aren't exclusive. B and C combine; A and B answer the same moment in two places (A in the Manual, B without leaving the host).

Keys to the answer⌘K, type, ↵. Three, and you never leave dc01. ⌘↵ copies and logs it against dc01 as "Kerberos errors: KRB_AP_ERR_SKEW".
GoodFastest by a step and no context switch, which is the exam-hour-14 case. ⌘K already knows the host and credential, so the fill is free. The Manual stays the place to read.
RiskNeeds a rule for which tables are "lookups" (proposal: a table whose first column is codes and that has a "Do this" column; or a lookup: true line in the note's frontmatter). The palette gets taller when a hit has many commands. Only helps rows, not prose.
C · Rail opens on /The note list folds away; the note gets the full width. / (or the note button) opens the list over the note, filter already focused. ↵ opens the pick, closes the list and puts focus in the note.

Keys to a named note/, type, ↵. Three, and you're reading (today it's six: M, /, type, ↵, then Esc and M to get focus into the note).
GoodAt 900px the note gains the 260px the rail takes today, enough for this table as columns instead of stacked blocks. Nothing on screen but the note. Same key as today, so nothing to relearn.
RiskYou lose the at-a-glance list of notes, and with it browsing by eye. The open note's name moves to the header button. Mouse use needs a click on that button first.
A middle wayFold the rail only below 1280px and keep it pinned above, so the wide-screen layout stays as it is today.
